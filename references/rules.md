# 设备三视图输入与验收契约

## 交付边界

本工具处理包内中文三视图 YAML。物理视图入口声明 `所属实体`、`安装视图`、`数据视图`，可引用 `模板`。三个视图描述同一套设备。型号模板跨项目复用；槽位、PV 前缀、IOC、测点接线等属于部署实例。不同专业独立写文件，定义同一个 ID 的责任只归一方。通用数据字典、机理资料与现场证据由维护者保留出处和版本。

| 视图 | 源码规则 | 工具检查 |
|---|---|---|
| 实体 | 每个实体有 ID、类型和同目录约定下的 `历史/ID.yaml`。实体可嵌套，接口按类型列名。 | 全局 ID 与端口唯一、历史 ID 匹配、两端存在且类型兼容。安装视图可用 `独占接口类型` 列表配置独占约束，默认 MicroTCA AMC 插槽。 |
| 数据 | 进程的主机和目标分别记录。控制路径是按访问顺序排列的数据接口。每个 IOC 有本地全文 PV 名录，每行一个名称。 | 主机和目标为实物，接口有实物承载，路径包含有效节点，端点对应声明的主机和目标。发布名称跨 IOC 唯一。逐通道和逐卡的命名规则均须在所属 IOC 清单中展开成功。 |
| 物理 | 模型可直接引用专业文档。对输入、参数、输出注明物理含义、单位、位置、工况与标定依据。 | 若模板声明适用型号，则与实物比对。测量引用的探头须接到所声明输入；文档引用须存在；文档量名须能通过命名规则绑定到该卡 PV。 |

每份实体历史的字段是 `实体ID` 和列表 `操作记录`。软件或物理视图中的实体也使用项目历史目录（入口文件旁）。缺少依据的单位、坐标、电极方位、实际权限、供应商文档版本，不凭命名推断。槽位到交换端口的电气映射、实机 IOC 名录完整性、板卡操作是否安全及历史记录真实性仍需现场核对。

## 导入与宏

任意映射内可声明 `导入` 列表。项为相对当前文件的路径，或包含 `文件` 和 `参数` 的映射。顶层键合并到导入处；嵌套导入显式传参。模板键和值均可用 `${名称}`；整值替换保留类型。宏不会执行代码。文件缺失、循环、缺参、多参和键冲突均会失败。数据视图的 `{前缀}`、`{通道}` 属于第二阶段，只有展开部署实例后才计算。运行前确认输入来源，导入只用于本地项目资料。

## OWL 投影与推理测试

工具把三视图编译为 RDF/XML 编码的 OWL。实体类型为 OWL 类，实物、进程、端口、路径及有序跳点、文档、物理量与 PV 为带独立 IRI 的资源；属性和资料路径为字面量。端口和嵌套实体用 `partOf`，接线用 `connectedTo`，设备控制和进程部署分别用 `controls`、`runsOn`。物理文档经 `describes` 关联实例量，经 `boundPV` 查到数据点，再经 `publishedBy` 查到 IOC。完整 PV 清单也保留单独的诊断点。

扩展验收时参照样例 `验收.yaml`。三元组的两端按 `[资源种类, ID, ...]` 寻址，谓词使用词表短名。用例支持“存在”（显式或推得）、“推得”（闭包中新增）、“未导出”（闭包中没有）。例如 `[[entity, CPU板01], hosts, [entity, 板卡控制进程01]]` 应由 `runsOn` 的逆关系推得。工具物化 OWL 2 RL 闭包，检查引擎报告的矛盾及每条用例。开放世界下，“未导出”不能证明命题为假。名称唯一、漏配 PV 等封闭数据检查在编译前执行。

输出覆盖包内示例的关系；仅列作证明材料的 Markdown、历史记录正文和任意自定义 YAML 字段不会自动成为 OWL 公理。新增行业规则或字段时，同时补充其语义映射、反例和验收用例，再将该能力列为已支持。
